## 生产加固补全：结构化 JSON 访问日志 + 请求 ID 贯穿

对照全栈专家 Phase 2 清单，补齐最后一项基础设施（原 `log_message` 为静默 `pass`）。

- `web.py`：
  - 导入新增 `logging` / `uuid` / `datetime`
  - 模块级 `_access_logger`（logger 名 `library.access`）：JSON 行输出到 **stderr**（不污染业务 stdout，便于采集）
  - `ApiHandler.__init__`：每个请求生成 `self._req_id`（uuid 前 12 位）+ `self._req_start`（时间戳）。**必须在 `super().__init__()` 之前设置**——基类 `__init__` 内部会调用 `handle()→请求处理→send_response()→log_request()`，彼时就要用到这两个字段（初版放在 super 之后导致 `AttributeError: _req_id`，已修）
  - `ApiHandler.log_request`：覆盖默认（原静默）。输出结构化 JSON：`{ts, req_id, method, path(去 query), status, ms, client}`。守卫 `if code == '-': return` 跳过 `handle_one_request` 末尾的无参兜底调用，避免重复/无意义日志
  - `_fail`：错误响应 payload 新增 `req_id`，客户端可凭此关联访问日志排障
- 输出示例：`{"ts":"2026-10-23T21:00:00","req_id":"a1b2c3d4e5f6","method":"GET","path":"/api/admin/logs","status":401,"ms":1.2,"client":"127.0.0.1"}`
