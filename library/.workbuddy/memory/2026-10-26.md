# 2026-10-26 工作记录

## 本轮交付：密码加盐哈希（修复明文存储严重安全漏洞）

### 问题
- `user_repo.insert` 直接落库明文密码；`user_service.login` 用 `row[2] != password` 明文比对；`user_repo.password_matches` 用 SQL `password = ?` 明文比对。即**密码明文存储**，属严重安全缺陷。

### 新增 `core/security.py`（零第三方依赖，仅标准库）
- `hash_password(pwd)`：PBKDF2-HMAC-SHA256，每用户 `os.urandom(16)` 随机盐，迭代 200000；存储格式 `pbkdf2_sha256$<iters>$<salt_hex>$<hash_hex>`。
- `verify_password(pwd, stored)`：哈希格式走正常校验（hmac.compare_digest 防时序攻击）；非本格式按遗留明文比较（向后兼容）。
- `is_legacy_plaintext(stored)`：判断是否为待升级明文。

### 改造
- `service/user_service.py`：
  - `register`：入库前 `security.hash_password`。
  - `login`：改 `security.verify_password`；成功且为遗留明文时**就地升级为哈希**（避免长期明文留存）。
  - `modify_password` / `reset_password_by_qa`：写入前哈希。
- `repository/user_repo.py`：`password_matches` 改为取出存储值后在 Python 层 `security.verify_password`（不再 SQL 明文比对）；模块顶部加 `from core import security`。
