## 本轮交付：前端请求韧性（5xx 幂等重试 / 离线提示 / 并发刷新去重）

### 背景
全栈专家 Phase 4 前端边界要求：4xx 不重试、5xx 自动重试（最多 3 次）、fetch 失败显示离线提示。
原 `static/index.html` 的 `api()` 仅处理 401 自动续期，无 5xx 重试、无退避、无离线提示。

### 改动（仅 `static/index.html`）
- `api()` 重构为循环 + 重试：
  - **5xx / 网络错误**：仅对**幂等方法**（GET/HEAD/OPTIONS/PUT/DELETE）自动重试，最多 3 次，指数退避 300/600/1200ms（上限 3000）；POST 不重试，避免重复借书/扣款等副作用。
  - **4xx**：不重试（401 走刷新流程）。
  - **网络错误**（fetch 抛异常）重试耗尽后调用 `showOffline()` 弹「网络连接失败，请检查网络后重试」。
  - 401 刷新后仅重试一次；刷新失败 `logout()`。
- 新增纯函数 `isIdempotentMethod` / `isRetryableStatus` / `backoffDelay` / `sleep` / `showOffline`，用 `// ==RETRY-BEGIN== / ==RETRY-END==` 标记包裹便于测试。
- **修复潜在并发 bug**：原 `refreshing` 布尔守卫在并发 401 时会让后到请求误登出；改为 `refreshPromise` 去重——并发 401 共享同一次 `/api/refresh`，均正确重试不登出。
- 移除已废弃的 `refreshing` 变量声明。
